# QAT seed sweep and U250 trade-off

Generated by `python scripts/plot_qat_sweep.py` from `results/fp32_kd_sweep`, `results/qat_sweep`
and `results/hw`. 240 runs: 2 students (TestResNet, slim 128/64) × input 160/192/224 ×
2 teachers (ResNet18 teacher assistant, ResNet50 direct) × FP32/8w8a/6w6a/4w4a × seeds 42–46.
Each seed also draws a new patient split; every QAT run starts from the FP32 checkpoint with the
same seed, split, student and teacher. Test sets have 133 images.

## Findings

| Precision | Mean test accuracy (60 runs) | Change vs FP32, paired (95% t interval) |
| --- | ---: | ---: |
| FP32 | 82.3% | — |
| 8w8a | 82.1% | −0.2 pp [−0.9, +0.4] |
| 6w6a | 81.0% | −1.3 pp [−2.0, −0.6] |
| 4w4a | 58.6% | −23.7 pp [−25.0, −22.5] |

- 8-bit is indistinguishable from FP32; 6-bit costs about one point; 4-bit fails in every configuration.
- Teacher, input size and slim vs full differences are within the seed-to-seed spread (SD ≈ 2–4 pp).
- On the U250, slim 128/64 at 160 input has the highest ceiling: 3,810 FPS at 15.9% of the LUTs
  (6-bit, 81.1% accuracy). TestResNet 224 saturates near 1,960 FPS whatever the area.
- For slim 6w6a, going from 108 to 3,810 FPS (35×) costs 1.77× the LUTs but 45× the DSPs;
  most LUT, FF and BRAM use is a fixed cost of the design.

## Caveats

- Intervals are nominal: seeds share one dataset and their test splits can overlap.
- U250 FPS values are FINN analytical estimates at 100 MHz for the accelerator alone, not board
  measurements; resources are post-synthesis. Builds were made from earlier single-seed checkpoints;
  throughput and area depend on architecture, input size and bit-width, not on the trained weights,
  so the plot pairs them with the sweep accuracy of the same configuration. The 224 builds used the
  untrimmed preprocessing; their accuracy label comes from the trim224 sweep.
- Both teachers are fixed checkpoints; whether they saw patients that fall in a student's test split
  is not recorded (see `analysis/kd_u250/README.md`).
