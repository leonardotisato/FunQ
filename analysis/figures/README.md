# Figures

Generated by `python scripts/make_figures.py` from `results/`. Figures are PNG at 300 dpi. Widths match IEEEtran conference: `fp32_teachers_*` and
`qat_precision*` are text width (`figure*`, 7.16 in); the others are column width (3.5 in).
The numbers behind each plot are in `data/`.

## Shared encoding

| Channel | Meaning |
| --- | --- |
| Colour (blue / orange / green) | Input size 160 / 192 / 224 px |
| Solid vs hatched bar; filled vs hollow marker | Architecture: **Base** vs **Slim** |
| Marker shape (circle / triangle) | Bit-width: 6-bit / 8-bit (weights and activations) |
| Full vs light colour | Teacher: **TA** (ResNet18 teacher assistant) vs **Direct** (ResNet50), only in `fp32_teachers_*` |

**Base** is `test_resnet.r160_in1k` (373k parameters); **Slim** is Base with the last two stages
narrowed to 128 and 64 channels (218k parameters). "8-bit"/"6-bit"/"4-bit" means 8w8a/6w6a/4w4a QAT.

## Captions

**`fp32_teachers_accuracy`** (also `_f1_weighted`)
> Full-precision test accuracy of each student and input size, distilled from the ResNet18
> teacher assistant (full colour) or directly from ResNet50 (light). Bars: mean of 5 seeds;
> whiskers: 95% t interval. Each seed draws a different patient split. The y-axis starts at 60%.

**`qat_precision_accuracy`** (also `_f1_weighted`)
> Test accuracy after quantization-aware training at 8 and 6 bits, next to the FP32 starting
> point. Bars: mean of 10 runs (5 seeds × 2 teachers), value on top; whiskers: 95% t interval.
> Each QAT run starts from the FP32 checkpoint with the same seed, split, student and teacher.
> The y-axis starts at 70%. 4-bit (57.7–60.6%) is shown in `qat_precision_with_4bit_*`.

**`qat_precision_with_4bit_accuracy`** (also `_f1_weighted`)
> As above, including 4-bit QAT; the y-axis starts at 50%.

**`u250_max_throughput`**
> Maximum throughput of each configuration on the Alveo U250 (FINN dataflow accelerator at
> 100 MHz). Slim at 160 px reaches 3,810 FPS at both 6 and 8 bits; Base
> at 224 px is limited to 1,958 FPS.

**`u250_accuracy_vs_throughput`**
> Mean QAT test accuracy (10 runs) against the maximum U250 throughput of each built configuration
> (`u250_max_throughput`). 6- and 8-bit builds of the same model reach the same throughput: FINN picks
> the same parallelism for both, and bit-width only changes area.

**`u250_slim160_6bit_area_vs_throughput`**
> U250 resources (post-synthesis, % of the device) used by Slim, 160 px, 6-bit, built for
> increasing throughput. From 108 to 3,810 FPS (35×) LUTs grow 1.8× and DSPs 45×; most LUT,
> FF and BRAM use is independent of throughput. BRAM counts an 18K block as half a 36K block.

## Notes for the text

- Paired QAT − FP32 change (same seed, split, student and teacher; `data/paired_change_vs_fp32.csv`),
  60 pairs per bit-width: 8-bit −0.2 pp [−0.9, +0.4], 6-bit −1.3 pp [−2.0, −0.6], 4-bit −23.7 pp [−25.0, −22.5].

- Teacher, input size and architecture differences are within the seed-to-seed spread
  (SD 2–4 pp on 133 test images); the figures do not support ranking them.
- The U250 builds were made from earlier single-seed checkpoints. Throughput and area depend on
  architecture, input size and bit-width, not on the trained weights, so `u250_accuracy_vs_throughput`
  pairs each build with the sweep accuracy of its configuration. The 224 px builds used the untrimmed
  preprocessing; the trim is a host-side crop and the accelerator only adds normalization, so the
  hardware is identical and their accuracy comes from the 224 px (trimmed) sweep.
- All 240 sweep runs use the black-border trim at every input size. Slim reports do not record
  `student_preprocess`, but the slim scripts apply `trim_fundus_black_border` to all splits.
- Intervals are nominal: seeds share one dataset and their test splits can overlap.
